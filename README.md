# 臺南市雨水下水道缺失圖台

雨水下水道縱走調查成果的互動式地圖，含缺失分級、工程契約分配、現況照片與使用者定位。純靜態網站，可直接放上 GitHub Pages，支援手機安裝為 App（PWA）。

**2,255 筆缺失點位 ｜ 1,590 張現況照片 ｜ 5 個行政區**

---

## 一、部署到 GitHub Pages

```bash
git init
git add .
git commit -m "臺南市雨水下水道缺失圖台"
git branch -M main
git remote add origin https://github.com/<你的帳號>/<repo 名稱>.git
git push -u origin main
```

推上去後到 repo 的 **Settings → Pages**：

- Source 選 **Deploy from a branch**
- Branch 選 **main**、資料夾選 **/ (root)**
- 存檔後等一兩分鐘，網址是 `https://<帳號>.github.io/<repo>/`

全部路徑都是相對路徑（`./`），放在子目錄也能正常運作，不需要改任何設定。倉庫內已附 `.nojekyll`，避免 GitHub 的 Jekyll 處理干擾檔案。

### 想改成自訂網域

在 repo 根目錄新增一個 `CNAME` 檔，內容寫網域名稱即可，其餘不用動。

## 二、手機使用

### 安裝為 App

- **Android / Chrome**：開啟網站 → 右上選單 → 「加到主畫面」
- **iPhone / Safari**：開啟網站 → 分享鈕 → 「加入主畫面」

安裝後以全螢幕開啟，離線也能看地圖範圍、缺失點位與看過的照片（Service Worker 會快取程式、資料與最近瀏覽過的底圖磚與照片）。

### 操作方式

| 動作 | 說明 |
|---|---|
| 下方抽屜 | 可拖曳，分三段：收合 → 一半 → 全開；也可點頂部的篩選鈕切換 |
| 定位鈕 | 右上圓形按鈕。允許定位後，清單改為**依距離排序**，並出現搜尋半徑滑桿（100 m～3 km） |
| 點圓點 | 顯示缺失明細、工程契約、現況照片，並提供 Google 導航與地圖 App 連結 |
| 放大地圖 | 縮放到街廓層級（zoom 16 以上）會自動標出缺失標籤 |

> 定位功能需要 HTTPS。GitHub Pages 預設就是 HTTPS，可直接使用；若用 `file://` 直接開啟本機檔案則無法定位。

## 三、功能

- **白色霧面遮罩**：臺南市以外一律遮白，只呈現市轄範圍，並繪出 37 個行政區界
- **五軸篩選**：工程契約、行政區、缺失類別、改善狀態、缺失等級，可交叉並帶關鍵字搜尋
- **兩種上色**：依缺失等級（A/B/C/未分級）或依工程契約（C1～C6、C0）
- **使用者定位**：即時位置、精度圈、依距離排序、半徑篩選
- **匯出**：把目前篩選結果存成 GeoJSON 或 CSV（UTF-8 with BOM，Excel 可直接開）

## 六、資料處理說明

1. **綜合等級**：屬性表「等級／CLASS」欄全為空，實際分級記在各分項欄位（破損位置／破損狀況／破損面積、淤積深度比／淤積狀況、不明管材質／占斷面比例、附掛位置／附掛情形）。本圖台取各分項中最嚴重者（A > B > C）。「無法縱走」表無等級欄位，列為未分級。
2. **改善狀態**：屬性表 DEV_OK／DEV_DATE／DEV_GRP 三欄皆為空值。目前已改善 43 筆＝仁德區破損表末欄註記「114年公所開口契約已改善」30 筆＋計畫表歸類「另案已處理」13 筆。日後填入 DEV_OK（Y／是／已改善）即可自動認列。
3. **點位比對**：計畫表 400 列有效資料，以行政區＋照片編號＋起算人孔＋距離、或 TWD97 座標一對一比對；363 列對應到既有縱走點位，24 列為新增點位。
4. **概略位置**：計畫表中 24 列沿用同一管段座標（例如中西6~20 皆使用中西5 的 X／Y），圖上以虛線圓圈微幅散開以利點選，匯出檔仍保留原始 X／Y。
5. **東區 13 筆未上圖**：其 X／Y 與安平區 CAPR182-R1 完全相同（表單複製所致），落點不在東區，故排除。其中含規劃第一年度 1 筆（東(德慶溪)7 育樂街）、規劃第二年度 3 筆、其它 9 筆，補上正確座標即可併入。
6. **鄰近路段**：計畫表第 88 欄對新增列為沿用同管段的粗略路名，實際地址在第 21 欄，已改用後者並新增「詳細位置」欄位（帶門牌與地標）。
7. **座標**：原始 X／Y 為 TWD97 TM2 二度分帶（EPSG:3826），已轉為 WGS84 供網頁地圖使用，並逐點驗證落在其標示的行政區界內。

## 七、資料更新

只要替換 `data/records.json`（欄位格式不變），地圖、統計與匯出都會跟著更新。更新後把 `sw.js` 第一行的 `VERSION` 改成新值（例如 `v2`），使用者下次開啟時就會取得新資料，不會被舊快取卡住。
